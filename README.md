# Mauri AI — دليل النشر الكامل (GitHub → Vercel)

**تطوير: Mauritech**

هذا المشروع جاهز للنشر مباشرة على Vercel عبر GitHub، ويتضمن:
- `public/index.html` — الواجهة العامة (دردشة + فرص وإعلانات + تقديم طلبات)
- `public/admin.html` — لوحة التحكم (وكيل الأعمال، الفرص، الشركات، ربط الحسابات، التقارير)
- `api/` — دوال خادم (Serverless Functions) على Vercel: الدردشة، البيانات، فيسبوك

---

## الخطوة 1 — رفع المشروع على GitHub

1. أنشئ مستودعاً جديداً (Repository) على GitHub، مثلاً باسم `mauri-ai`.
2. من جهازك (بعد تحميل ملفات المشروع من هنا)، داخل مجلد المشروع نفّذ:
   ```bash
   git init
   git add .
   git commit -m "أول نسخة من مشروع Mauri AI"
   git branch -M main
   git remote add origin https://github.com/USERNAME/mauri-ai.git
   git push -u origin main
   ```
   (استبدل `USERNAME` باسم حسابك على GitHub)

---

## الخطوة 2 — ربط المستودع بـ Vercel

1. ادخل إلى [vercel.com](https://vercel.com) وسجّل دخول بحساب GitHub.
2. اضغط **Add New → Project**.
3. اختر مستودع `mauri-ai` من القائمة واضغط **Import**.
4. Vercel يكتشف تلقائياً أنه مشروع Static + Serverless Functions، لا حاجة لتغيير أي إعداد بناء (Build Settings) — اترك الحقول فارغة أو افتراضية.
5. اضغط **Deploy**.

بعد دقيقة تقريباً سيكون مشروعك منشوراً على رابط مؤقت من نوع `mauri-ai.vercel.app`.

---

## الخطوة 3 — ربط الدومين الذي تملكه على Vercel

بما أن الدومين موجود عندك مسبقاً على Vercel:

1. من صفحة المشروع في Vercel، اذهب إلى **Settings → Domains**.
2. اكتب اسم الدومين واضغط **Add**.
3. إذا كان الدومين مسجلاً مسبقاً تحت حسابك في Vercel، سيتم ربطه تلقائياً بدون أي إعداد DNS إضافي.
4. إذا كان الدومين مسجلاً خارج Vercel (عند مزود آخر)، سيعطيك Vercel سجلات DNS (A / CNAME) تضيفها عند مزود الدومين.

---

## الخطوة 4 — إضافة متغيرات البيئة (Environment Variables)

من **Settings → Environment Variables** أضف المتغيرات التالية (نفس الأسماء الموجودة في ملف `.env.example`):

| المتغير | من أين تحصل عليه |
|---|---|
| `ANTHROPIC_API_KEY` | من [console.anthropic.com](https://console.anthropic.com) → API Keys |
| `FB_APP_ID` | من [developers.facebook.com](https://developers.facebook.com) → تطبيقك → Settings > Basic |
| `FB_APP_SECRET` | نفس الصفحة أعلاه |
| `FB_REDIRECT_URI` | `https://your-domain.com/api/facebook/callback` (استبدل بدومينك الحقيقي) |
| `FB_VERIFY_TOKEN` | أي نص سري تختاره أنت، تضعه أيضاً فِ إعداد الـ Webhook فِ Meta |
| `WHATSAPP_TOKEN` | من تطبيقك → WhatsApp → API Setup (توكن مؤقت للتجربة، أو توكن دائم عبر System User) |
| `WHATSAPP_PHONE_NUMBER_ID` | من نفس صفحة WhatsApp → API Setup |
| `WHATSAPP_VERIFY_TOKEN` | أي نص سري تختاره أنت، تضعه أيضاً فِ إعداد Webhook واتساب |

بعد إضافتها، اضغط **Redeploy** لتفعيلها.

---

## الخطوة 5 — إنشاء قاعدة بيانات Vercel KV (لحفظ الطلبات والفرص بشكل دائم)

1. من لوحة المشروع في Vercel، اذهب إلى تبويب **Storage**.
2. اضغط **Create Database → KV**.
3. اربطها بالمشروع (Connect to Project) — سيضيف Vercel تلقائياً متغيرات `KV_REST_API_URL` و`KV_REST_API_TOKEN`.
4. أعد النشر (Redeploy) بعد الربط.

بدون هذه الخطوة، ستعمل الواجهات لكن بيانات الفرص/الشركات/الطلبات لن تُحفظ بين الزيارات.

---

## الخطوة 6 — إعداد تطبيق فيسبوك (لربط صفحة الأعمال ومكتبة الإعلانات)

1. ادخل [developers.facebook.com](https://developers.facebook.com) → **My Apps → Create App** → اختر نوع **Business**.
2. من **Settings → Basic**، انسخ App ID و App Secret إلى متغيرات البيئة في Vercel.
3. من **Add Product**، أضف منتج **Facebook Login**.
4. في **Facebook Login → Settings**، أضف تحت "Valid OAuth Redirect URIs":
   ```
   https://your-domain.com/api/facebook/callback
   ```
5. لتفعيل ربط صفحة حقيقية لأي مستخدم غير فريقك (وليس فقط أنت كمطوّر التطبيق)، يجب إرسال التطبيق لمراجعة **App Review** من Meta وطلب الصلاحيات: `pages_show_list`, `pages_read_engagement`, `pages_manage_posts`, `pages_messaging`. هذه المراجعة تقوم بها Meta نفسها وقد تستغرق أياماً — هذه خطوة إلزامية من طرفهم ولا يمكن تجاوزها بالكود.
6. أثناء التطوير والاختبار، يمكنك ربط صفحتك الخاصة مباشرة بصفتك مطوّر التطبيق (Admin/Developer/Tester على التطبيق) بدون انتظار المراجعة.
7. **لتفعيل الرد التلقائي على ماسنجر (وكيل الأعمال):**
   - من **Add Product**، أضف منتج **Webhooks**.
   - اضغط **Subscribe to this object** لنوع **Page**.
   - Callback URL: `https://your-domain.com/api/facebook/webhook`
   - Verify Token: نفس قيمة `FB_VERIFY_TOKEN` التي وضعتها فِ متغيرات البيئة.
   - اشترك فِ الحقل `messages` (و`messaging_postbacks` إن أردت).
   - عند ربط صفحتك من زر "ربط صفحة فيسبوك" فِ لوحة التحكم، سيشترك الكود تلقائياً الصفحة فِ هذه الأحداث — لكن رابط الـ Webhook نفسه (الخطوة أعلاه) يجب إضافته يدوياً مرة واحدة من لوحة Meta، وهذه خطوة تفرضها Meta على مستوى التطبيق وليس على مستوى الصفحة.

**مكتبة إعلانات المنافسين (Ads Library)** تعمل بدون App Review لأنها بيانات عامة — تحتاج فقط App ID و App Secret صحيحين.

## الخطوة 7 — واتساب بزنس (الرد التلقائي عبر وكيل الأعمال)

1. من نفس تطبيق فيسبوك، أضف منتج **WhatsApp**.
2. من **API Setup**، ستجد رقم اختباري مجاني من Meta جاهزاً للتجربة فوراً — انسخ منه:
   - `Temporary access token` → ضعه فِ `WHATSAPP_TOKEN`
   - `Phone number ID` → ضعه فِ `WHATSAPP_PHONE_NUMBER_ID`
3. من نفس الصفحة، تحت **Webhook**، اضغط **Configure** وأدخل:
   - Callback URL: `https://your-domain.com/api/whatsapp/webhook`
   - Verify Token: نفس قيمة `WHATSAPP_VERIFY_TOKEN`
   - اشترك فِ الحقل `messages`
4. جرّب: ابعث رسالة من هاتفك للرقم التجريبي — يجب أن يردّ عليك وكيل الأعمال تلقائياً باللهجة الحسانية.
5. **للاستخدام الحقيقي (رقم دائم غير تجريبي)**: يتطلب حساب **Meta Business** موثّقاً، ورقم هاتف مخصص، وتوكن دائم عبر **System User** (بدل التوكن المؤقت الذي تنتهي صلاحيته كل 24 ساعة). هذه خطوات تُنجز من لوحة Meta Business Suite ولا يمكن تجاوزها بالكود.
6. **قاعدة مهمة من Meta نفسها:** يمكنك الرد بحرية على أي رسالة وصلتك خلال آخر 24 ساعة (وهذا ما يفعله وكيل الأعمال تلقائياً). لإرسال رسالة تبدأ بها أنت المحادثة (تسويق مثلاً)، يجب استخدام **قالب رسالة معتمد مسبقاً** من Meta — هذا قيد من واتساب لحماية المستخدمين من الإزعاج، وليس قيداً تقنياً من هذا المشروع.

## الخطوة 8 — تدريب الوكيل وذاكرته (بلا نشر كود جديد)

من تبويب **"تدريب الوكيل"** فِ لوحة التحكم:

- **اطلب تعديلاً:** اكتب أي طلب بصياغتك الطبيعية (مثلاً: "خلي ردوده أقصر")، ويُصاغ تلقائياً بالذكاء الاصطناعي كتعليمة واضحة وتُحفظ فِ قاعدة البيانات — تُطبَّق فوراً فِ **كل** رد جاي (دردشة، ماسنجر، واتساب) بلا الحاجة لإعادة نشر أي شيء.
- **قاعدة المعرفة:** معلومات ثابتة تكتبها أنت (أسعار، سياسات، ساعات العمل...) يستعملها الوكيل بدل ما يختلق إجابات.
- **آخر الأخبار:** تُجمع تلقائياً كل ساعة عبر مهمة مجدولة (`api/news/fetch.js` + Vercel Cron المُعرّف فِ `vercel.json`)، وتحتاج فقط `NEWS_API_KEY` من [newsapi.org](https://newsapi.org) (يوجد مستوى مجاني).

**مهم:** هذا كله تعديل على *سلوك* الوكيل (تعليماته وذاكرته)، وليس إعادة كتابة أو نشر كود جديد تلقائياً — وهذا مقصود ومطلوب أمنياً: لا يوجد نظام إنتاجي جدي يسمح لذكاء اصطناعي بتعديل الكود المنشور فعلياً بلا مراجعة بشرية، لأن أي خطأ فِ التوليد قد يعطّل الموقع بالكامل.

## حدود واقعية يجب معرفتها

- **"يعرف كل المعلومات":** غير ممكن لأي نظام ذكاء اصطناعي. الوكيل يعرف معرفته العامة + ما تضيفه أنت فِ "قاعدة المعرفة" + آخر الأخبار المحفوظة.
- **بناء مواقع/تطبيقات:** الوكيل يكتب لك الكود كنص جاهز فِ المحادثة تنسخه وتستعمله — لا ينشره ولا يعدّل أي مشروع حي بنفسه.
- **الاستثمارات:** الوكيل يعطي معلومات ومقارنات عامة، وليس بديلاً عن مستشار مالي مرخّص لقرارات كبيرة.
